# Backend Requirements Specification

| ID | Description | Source | Priority | Backend Impact | Status |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **REQ-001** | **Authoritative Serviceability Verification**: Verify service availability and 1-Day Promise SLA eligibility by Nashik locality and PIN code. | PRD / Frontend | High | `POST /api/serviceability/check`, ServiceabilityService | Implemented |
| **REQ-002** | **Service Areas Directory**: Return operational hubs, average ETAs, coordinates, and active pro counts for Nashik corridors. | PRD / Frontend | Medium | `GET /api/serviceability/areas`, ServiceAreaConfig | Implemented |
| **REQ-003** | **Authoritative Booking Creation Engine**: Compute bills server-side (visit fee, labor, discount, taxes), auto-match eligible verified technician, generate 4-digit OTP and 24-hr promise deadline. | PRD / Core SLA | Critical | `POST /api/bookings`, BookingService, dynamic matching | Implemented |
| **REQ-004** | **Booking Lifecycle State Machine**: Enforce strict status transitions (`Requested` → `Confirmed`/`Assigned` → `On the Way` → `Arrived` → `Started` → `Completed`/`Cancelled`/`Disputed`). | PRD / Ops | Critical | `PATCH /api/bookings/:id/status`, State Transition Matrix | Implemented |
| **REQ-005** | **On-Site OTP Verification**: Verify 4-digit customer OTP upon technician doorstep arrival before transitioning to `Started`. | PRD / Security | High | `POST /api/bookings/:id/verify-otp`, BookingService | Implemented |
| **REQ-006** | **Booking Cancellation & Refund**: Support role-aware cancellation (customer vs ops) with automated refund status updates. | PRD / Finance | High | `POST /api/bookings/:id/cancel`, Audit Log | Implemented |
| **REQ-007** | **Google OAuth Server-Side Token Verification**: Authoritatively decode and verify Google ID tokens, resolving system roles (`admin`, `provider`, `customer`). | PRD / Security | High | `POST /api/auth/google`, AuthService | Implemented |
| **REQ-008** | **Real-time Maps Grounding**: Interface with Google GenAI (`gemini-3.5-flash` with Google Maps tool) for Nashik local hardware parts, route conditions, and landmarks. | PRD / Gemini AI | Medium | `POST /api/maps/grounding`, AIGroundingService | Implemented |
| **REQ-009** | **Nashik Transit & Route Advisor**: Provide route suggestions, landmark checkpoints, and ETA insights for technicians. | PRD / Gemini AI | Medium | `POST /api/maps/route-advisor`, AIGroundingService | Implemented |
| **REQ-010** | **Provider Duty State Management**: Allow verified providers to toggle online/offline duty status. | PRD / Provider | High | `PATCH /api/providers/:id/duty`, ProviderService | Implemented |
| **REQ-011** | **Provider Payouts & Commission Engine**: Compute 15% platform commission and 85% net provider earnings; execute instant UPI payout settlement. | PRD / Finance | High | `POST /api/providers/:id/payout`, ProviderService | Implemented |
| **REQ-012** | **Provider Partner Onboarding Pipeline**: Handle applications with trade experience, vehicle details, government IDs, and automated admin review queue. | PRD / Ops | High | `POST /api/providers/apply`, `GET /api/providers/application-status/:userId` | Implemented |
| **REQ-013** | **Admin Partner Application Review**: Allow super admin to approve/reject applications with auto-provisioning of provider profile upon approval. | PRD / Admin | High | `PATCH /api/admin/provider-applications/:id/review` | Implemented |
| **REQ-014** | **Admin Command Center Overview**: Aggregate gross booking value, platform revenue, active jobs, duty pros, SLA compliance rate, and live dispatch queues. | PRD / Admin | High | `GET /api/admin/overview`, OperationsService | Implemented |
| **REQ-015** | **Admin Dispatch Reassignment Override**: Allow admin to manually reassign bookings to different technicians with reason tracking. | PRD / Admin | High | `PATCH /api/admin/bookings/:id/reassign` | Implemented |
| **REQ-016** | **Client Push Device Registration**: Register web/PWA/mobile push device tokens, user roles, browser info, and permission states. | PRD / Notifications | High | `POST /api/notifications/devices/register` | Implemented |
| **REQ-017** | **User Notification Inbox & Preferences**: Provide inbox notifications, unread counters, mark-as-read endpoints, and opt-in/opt-out toggles. | PRD / User Experience | Medium | `GET /api/notifications/user`, `PATCH /api/notifications/user/preferences` | Implemented |
| **REQ-018** | **Admin Push Notification Composer & Scheduler**: Broadcast instant push messages or schedule future campaigns with audience segmentation. | PRD / Marketing & Ops | High | `POST /api/notifications/admin/jobs`, Background Worker | Implemented |
| **REQ-019** | **Notification Audience Resolution Engine**: Dynamically target users by role (`customers`, `providers`, `all_users`), locality, active bookings, or past history. | PRD / Notifications | High | NotificationService.resolveAudienceUserIds | Implemented |
| **REQ-020** | **Payment Initiation & Confirmation**: Authorize payment sessions, record transaction tokens, and confirm digitized invoice generation. | PRD / Finance | Medium | `POST /api/payments/initiate`, `POST /api/payments/confirm` | Implemented |
| **REQ-021** | **Customer Reviews & Ratings**: Submit verified reviews for completed bookings, update provider rating scores, and return public feed. | PRD / Customer Trust | Medium | `GET /api/reviews`, `POST /api/reviews` | Implemented |
| **REQ-022** | **Customer Support Ticketing**: Create support tickets, assign Nashik central coordinators, and maintain chat message history. | PRD / Customer Support | Medium | `GET /api/support/tickets`, `POST /api/support/tickets` | Implemented |
| **REQ-023** | **Immutable Audit Logging**: Record every critical state change (reassignments, approvals, payments, status updates) with actor, role, and before/after states. | PRD / Compliance | High | `GET /api/admin/audit-logs`, AuditRepository | Implemented |
| **REQ-024** | **Analytics Funnel Event Tracking**: Capture platform events (searches, bookings, payments, reviews) with structured metadata. | PRD / Analytics | Medium | `GET /api/operations/analytics`, OperationsService | Implemented |
| **REQ-025** | **System Health & Diagnostics**: Report uptime, component status (APIs, Gemini AI, Dispatcher, Notification bus), and error rates. | PRD / SRE | Medium | `GET /api/health`, `GET /api/admin/system-health` | Implemented |
